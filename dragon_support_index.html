Private settings: how to load dragon_support_settings.json (click to show / hide)

Your sample points, site order and the wind GO / ASSESS / NO-GO table are not stored in this page. They live in a private file, dragon_support_settings.json, that you keep off the public repository. Until it is loaded, the points box is empty and wind status shows "–".

  1. Get dragon_support_settings.json from your team's private share (not from GitHub).
  2. Open Sample points & map framing below and click Load settings file….
  3. Pick the JSON file. The status line under the buttons should read "Private settings loaded", the points fill in, and the tables and maps refresh.
  4. The settings are kept only in this browser on this computer, so you only need to load them once per computer and browser.

To update the file: edit the points in the box, then click Save settings file to download a new copy (the risk table carries over), and replace the copy on your private share.
On a shared or borrowed computer: click Forget on this computer when finished.

Point samples

How this is made

Samples are NBM CONUS values at the requested valid time, taken at the single NBM grid point nearest each site (2.5 km grid). Ceilings are rounded to METAR-reportable heights: 100 ft steps to 5,000 ft, 500 ft steps to 10,000 ft, then 1,000 ft steps. Thunder probability is NBM's TSTM probability for the same 1-h or 6-h window as the PoP. PoP comes from NBM core files on NOAA's AWS bucket. It uses the 1-h window ending at the valid time. If NBM has no 1-h value there, it uses the 6-h window ending at or containing the valid time. Mean wind comes from the NBM core 10 m wind, with Open-Meteo as a single-point backup. Wind exceedance probability comes straight from NBM's QMD files on NOAA's public AWS bucket (noaa-nbm-grib2-pds). It uses the hourly 10 m WIND record for the latest cycle that covers the valid time. NBM-native thresholds (7, 11, 17, 22, 30, 34, 48, 64 KT) use NBM's own probability. Other thresholds use NBM's ensemble mean and standard deviation with a gaussian assumption.

Point Forecast Time Series

One site, one parameter, hourly, sampled within 10 NM like Point samples
Forecast time series: one run, hours around the valid time (click to show / hide)

The model blend uses the sources ticked under Point samples › Model sources, with the same weights, 10 NM sampling and member pooling. In the blend, PoP and lightning are the weighted chance across sources.

Flight categories apply to ceiling and visibility only; other parameters fall back to thresholds.

How this is made

Each hour is read from the chosen model's GRIB2 file using the same 10 NM sampling as Point samples (mean of every grid point within 10 NM for wind, gust, ceiling, visibility, temperature and dew point; highest for PoP, thunder and precipitation). Model blend, RRFS ensemble and HRRR ensemble are worked out exactly like the Point samples tables (pooled members, source weights split across members, ceiling and visibility as the members' median); the two ensembles use all of that model's members for this chart only and do not change the Point samples sources: NBM from NOAA's NBM bucket (the newest run that has the hour, else an older run or the nearest hour), RRFS deterministic and HRRR from NOAA's RRFS and HRRR buckets (newest run that reaches the hour). Wind is converted to KT, temperatures to °F, ceiling to FT (above 20,000 ft or none = Unlimited) and visibility to SM (METAR fractions). The gridded row and the graph use the same values. Threshold colouring: green, yellow beyond the caution value, red beyond the warning value. Image colour tables use the same scales as the maps. Ceiling and visibility always use flight categories.

Forecast look-back: how past runs forecast the valid time (click to show / hide)

Each point is one model run's forecast for the valid date and hour at the top of the page; the newest run is on the right. Colours follow "Colour by" above. RRFS ensemble members run every 6 h. NWS Forecast, Gridded LAMP and the Open-Meteo global ensembles keep no past runs, so the blend look-back leaves them out.

How this is made

For every run in the look-back window the page opens that run's own files on the NOAA archives (HRRR, RRFS, RRFS ensemble members and probabilities, NBM core and wind percentiles) and IEM's archive of GFS MOS / LAMP runs, takes the forecast for the selected valid hour, and works it out exactly like the Point samples tables: 10 NM sampling, members pooled with each source's weight split across its members, wind mean / 99th percentile / exceedance, weather chances, and ceiling / visibility as the members' median. HRRR ensemble at a run uses that run and the seven before it. The plume shows every member's value, the shaded band is the 10–90% range and the white line is the result used in the tables. Runs not posted yet, or older than the archive keeps, are skipped.

How this is made

WPC's surface analysis / forecast chart (fronts, isobars, high and low centres and NDFD weather) for the frame nearest the valid time on the selected day: short-range charts out to about 2.5 days, then the day 3–7 charts. Four frames are shown: the one nearest the valid time (outlined) plus the frame before it and the two after it. Each image is cropped to the West, with the east edge near the Four Corners and the bottom above the NDFD legend, and shows the chart only. WPC's own printed valid-time stamp, cut from the same image, sits above each chart so you can confirm which forecast was fetched. Frames come from the short-range charts every 6 h from the latest 00Z/12Z package, then the day 3–7 charts at 12Z. Use Open ↗ to see WPC's full chart.

Fallback source (optional, rarely needed)

The maps load by themselves from the model data site, like NBM and RRFS. A mirror is only used if that site has no Gridded LAMP files.

How this is made

Gridded LAMP is read first from pre-processed files (latest.json plus one small file per element and hour) at the GLMP files URL, normally a separate public GitHub Pages repository that only holds this NOAA output, or glmp/ next to the page: the newest complete hourly run is downloaded from NOMADS, decoded and cropped to the briefing area off the page, then drawn here exactly like the NBM and RRFS maps, with values at the nearest grid point. The line above shows the run used, how old it is, which elements came through (ceiling, visibility, wind speed and gust, sky cover, 1-h PoP, and the ceiling < 500 ft / visibility < 1 and < 3 SM probabilities (used for ceiling ≤ 500 ft and, interpolated, visibility ≤ 1 NM)) and the probability thresholds actually found in the files. Without those files (for example an emailed copy) the maps use the GLMP data URL below, if given.
Gridded LAMP (GFS-LAMP, hourly runs at HH30Z out to 38 h) drawn the same way as the NBM and RRFS maps. Files follow MDL's LAMP web-services list: hourly CONUS files (ceiling, visibility, 1-h PoP), fcsts_wspd (wind speed) and fcsts_cigp2 / visp2 (probabilities for the sample tables). GLMP has no wind-exceedance probability. NOAA's NOMADS server does not allow browser (cross-origin) reads, so live data needs a CORS-enabled mirror of the glmp/prod directory entered above.

How this is made

REFS (the operational RRFS ensemble) from NOAA's open data bucket, drawn the same way as the NBM Gridded maps. Runs every 6 h (00/06/12/18Z) out to 60 h. Wind, wind probability and PoP come from REFS's own ensemble products. REFS publishes no ceiling percentiles, so the ceiling map is the 50th percentile (median) worked out here, cell by cell, from the RRFS runs behind REFS: members m001–m005 and the deterministic RRFS for the same cycle, plus the same set from the cycle 6 h earlier (time-lagged), as many as are posted; "no ceiling" counts as the highest value. Labels are the value at the single nearest grid point (3 km).

How this is made

Deterministic RRFS (the operational control run) from NOAA's open data bucket, drawn the same way as the NBM Gridded and REFS maps. Runs hourly; the 00/06/12/18Z runs go out to 84 h. 10 m wind is the speed from the 10 m U and V winds; ceiling is the model's cloud ceiling. A single run has no probabilities, so the wind-exceedance and PoP maps show the share of the area within 10 NM of each point where the run has wind above the threshold, or more than 0.01 in of precipitation in the hour ending at the valid time (a neighbourhood probability, like REFS's). For each hour the newest run that has it is used, then the 3-hour fallback. Labels are the value at the single nearest grid point (3 km).

Data sources & notes

Wind exceedance threshold: NBM's own probabilities: 7, 11, 17, 22, 30, 34, 48, 64 KT; other values are estimated from mean and spread.

Imagery: drawn in the browser from NBM, RRFS and Gridded LAMP GRIB2 data; Esri satellite basemap.

Point values: api.open-meteo.com (models=ncep_nbm_conus: hourly precipitation_probability %, wind_speed_10m KT). Backup: thredds.ucar.edu NetCDF Subset Service, grib/NCEP/NBM/CONUS/Best. Variables: Total_precipitation_surface_1_Hour_Accumulation_probability_above_0p254 (%), Wind_speed_height_above_ground (m/s → KT).

ECMWF charts: charts.ecmwf.int open-charts API (CC-BY-4.0). The ceiling map comes from medium-cloud-parameters (layer ceiling, North America), using the run closest to the NBM run in use and the exact valid time or the nearest available step. The ENS visibility meteograms (aviation) come from the 00Z/12Z run closest to the NBM run. ECMWF draws its legends in metres and km. This page covers them with ft (ceiling) and NM (visibility) labels for the same colour bins: 150 m ≈ 0.1 NM, 350 m ≈ 0.2, 600 m ≈ 0.3, 800 m ≈ 0.4, 1.5 km ≈ 0.8, 3 km ≈ 1.6, 5 km ≈ 2.7, 10 km ≈ 5.4 NM. NBM ceiling (ft) and visibility (NM) at each point are added to the sample table.

Copying images: browsers don't let a page capture another site's map, so take screenshots: Snip mode, then Win+Shift+S (Windows) or Cmd+Shift+4 (Mac) around each card.

Refreshing the page or changing any input reloads all imagery and samples. Inputs are kept in the page URL, so a bookmarked link reopens the same setup.
